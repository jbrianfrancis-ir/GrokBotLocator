  <files>src/App/QueueDrainCoordinator.swift</files>
  <action>Add to the `@MainActor final class QueueDrainCoordinator`:
- `private var userIsPresent = false` — false is the safe default: a process that came up for a location event or a background refresh has nobody looking at it, and a coordinator that defaults to "present" would announce on exactly the path this plan exists to silence.
- `func setUserPresent(_ present: Bool)` — sets the flag and nothing else. No drain, no side effect; 04-13's scene-phase handler already calls `drainForeground()` separately on `.active`, and folding a drain in here would double it.
- In `start()`, set `userIsPresent = true` as the FIRST statement, before `hydrate()`. `start()` is reachable only from the root view's `.task`, so reaching it means a scene exists and is showing.
- In `drainForeground()`, change `model.apply(report.updates, announcing: true)` to `model.apply(report.updates, announcing: userIsPresent)`. Leave the 25-second budget, the `surfacingFailures: true` argument and the `model.show(notice:)` call exactly as they are: a notice is on-screen guidance that persists until something replaces it, not a spoken announcement, so it is correct to set it either way.
Update `drainForeground()`'s doc comment: it is still the named entry point an automatic location trigger calls (REQ-05's fourth drain opportunity), it still surfaces failures and deletes them from the queue file, and it now announces only when someone is actually present. Say plainly which LEARNINGS entry this closes and why `drainBackground()` is untouched (it already passes `announcing: false` and has its own budget).
Do not add a UIKit import, a `UIApplication` query, or a clock.</action>
