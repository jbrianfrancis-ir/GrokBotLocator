  <name>Task 1: GeofenceMonitoring and the CLMonitor-backed actor</name>
  <files>src/Triggers/GeofenceMonitor.swift</files>
  <action>`import CoreLocation` + `import Foundation`. This is the only file in src/ that may name `CLMonitor`.

`protocol GeofenceMonitoring: Sendable`:
- `func register(at coordinate: TriggerCoordinate) async` — register or replace the one region.
- `func currentCentre() async -> TriggerCoordinate?` — the registered region's centre, or nil.
- `func startObserving(onExit: @escaping @Sendable (Date) async -> Void) async` — begins consuming events; the closure fires once per exit, carrying the event's own `date`.
- `func stopObserving() async` and `func unregister() async`.

`actor CLMonitorGeofence: GeofenceMonitoring` with three constants declared once: `static let monitorName = "GrokBotLocatorTriggers"`, `static let conditionIdentifier = "last-ping-region"`, `static let radiusMetres: CLLocationDistance = 150`.
- A lazily-created `CLMonitor` held in a `private var monitor: CLMonitor?`, built with `await CLMonitor(Self.monitorName)` on first use. Fetching it must be a single actor-isolated helper that assigns before any other await uses it; comment that a second caller arriving during that await must not build a second monitor (LEARNINGS: an actor is reentrant at every await) — guard with an explicit `isCreating` flag or by awaiting a stored `Task<CLMonitor, Never>`, the latter preferred because it is a single assignment before the first suspension.
- `register(at:)` — `await monitor.add(CLMonitor.CircularGeographicCondition(center: CLLocationCoordinate2D(latitude:longitude:), radius: Self.radiusMetres), identifier: Self.conditionIdentifier)`. Always the SAME identifier: that is what replaces rather than accumulates. Also store the centre in a `private var registeredCentre: TriggerCoordinate?`.
- `currentCentre()` — CONFIRM from the live DocC page (https://developer.apple.com/documentation/corelocation/clmonitor and its `.json` form) whether `CLMonitor` exposes a per-identifier record accessor returning `CLMonitor.Record` whose `condition` can be cast to `CircularGeographicCondition`. If it does, read the centre back from the monitor — that is what makes the value survive a cold background relaunch. If the accessor cannot be confirmed, return `registeredCentre` only, and say plainly in the SUMMARY that cold-launch rehydration of the reference coordinate is therefore unavailable through this route. Do not guess a spelling.
- `startObserving(onExit:)` — store a `Task` iterating `for try await event in monitor.events`. Ignore events whose `identifier` is not `Self.conditionIdentifier`. On `event.state == .unsatisfied` call `onExit(event.date)`. On `.satisfied` do nothing (REQ-08 is exit-only). If `event.conditionLimitExceeded` or `event.authorizationDenied` is true, stop and leave the region unarmed rather than spinning. Never force-unwrap.
- `stopObserving()` cancels that task; `unregister()` calls `await monitor.remove(Self.conditionIdentifier)` and clears `registeredCentre`.
Header comment records the 150 m radius as a BACKSTOP decision this phase's requirements do not settle (see `backstop_truths`), and states that this file writes nothing to disk — the region held by the OS is the durable record, not a second coordinate store.</action>
