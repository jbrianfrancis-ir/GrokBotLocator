<context>
src/Ping/PingSender.swift — `PingSending.send(label:)` acquires its OWN fix via
`LocationFixProvider.currentFix()`. An automatic ping must not do that: the trigger already
carries a fix, and starting a fresh location session on a background wake is both slow and the
shape ARCHITECTURE's Forbidden continuous-GPS entry exists to keep out of this app.
src/Core/Ping/PingRateLimiter.swift (04-02) — `PingRateLimiting`.
src/Triggers/TriggerLabel.swift (04-04) — `TriggerLabelProviding`, `EmptyTriggerLabelProvider`.
src/Ping/PingHistory.swift (04-09) — `PingTrigger`, `PingDeliveryUpdate` with its trigger field.
src/App/QueueDrainCoordinator.swift (04-05) — why nothing on a wake path announces.
NOTE: the drain on a location wake is NOT this type's job. 04-11 drains on every callback, before
and independently of the rate gate, so a rate-limited wake is still a drain opportunity.
Gate: SMOKE_DERIVED_DATA=build/dd-04-10 ./scripts/smoke.sh. Swift Testing, never XCTest.
In-task vs fan-in (.planning/LEARNINGS.md): the grep and presence assertions in every `<verify>`
below are checkable in-task and are what this plan is accountable for. `smoke exits 0` — and any
`Suite … passed` log assertion, which needs the build to complete — is NOT reliably observable
mid-wave: per-plan `SMOKE_DERIVED_DATA` isolates the build LOG, not the SOURCES, so a whole-project
build compiles every sibling's in-flight edits. Run it and report verbatim what it said; a failure
traceable to a sibling's half-landed edit is deferred to the orchestrator's fan-in gate, and is
never licence to change this plan's own files to go green.

  <name>Task 2: AutomaticPinger</name>
  <files>src/Triggers/AutomaticPinger.swift</files>
  <action>`import Foundation`.
`enum AutomaticPingResult: Sendable, Equatable` — `case pinged(PingOutcome)`, `case rateLimited`, `case noCredentialsOrFix`. The caller needs to know whether a ping actually went out, because 04-11 advances its reference coordinate and re-registers the geofence only when one did.
`protocol AutomaticPinging: Sendable` — `func ping(fix: LocationFix, trigger: PingTrigger) async -> AutomaticPingResult`.
`@MainActor final class AutomaticPinger: AutomaticPinging` (main-actor because it folds results into `PingModel`, which is `@MainActor`), init taking `sender: any PingSending`, `labels: any TriggerLabelProviding`, `rateLimiter: any PingRateLimiting`, `model: PingModel`, `now: @Sendable () -> Date` — all five without defaults.
`ping(fix:trigger:)`:
1. `switch await rateLimiter.claim(at: now())` — on `.tooSoon` return `.rateLimited` immediately: nothing is sent, no history row is written, nothing is queued. Comment the reasoning: SC-04's ceiling exists precisely to suppress these, and an event the user never initiated is not a ping that was dropped — there was no ping. This is different from the MANUAL refusal in `PingModel`, which DOES tell the user, because there a person tapped and is waiting.
2. `let label = normalisedTriggerLabel(await labels.label(for: TriggerCoordinate(fix: fix)))`.
3. `let attempt = await sender.send(label: label, using: fix)`.
4. Map `attempt.disposition` to a `PingOutcome`/reason with the SAME three-arm switch `PingModel.ping()` uses (`.sent`/`.permanentFailure`/`.retryable` → `.sent`/`.failed`/`.queued`).
5. Build one `PingDeliveryUpdate` with `id: attempt.queuedID ?? UUID()`, the fix's own coordinate and timestamp, the label, the outcome, the reason and `trigger:`, and call `model.apply([update], announcing: false)`. Comment why `false` is not a judgement call here: `PingAttemptFeedback.spoken` renders every non-sent outcome as "Ping failed. …", which is a sentence about a tap, and no tap happened (04-05 settled the same question for the drain).
6. Return `.pinged(outcome)`, or `.noCredentialsOrFix` when the disposition is the permanent "Add your webhook URL and sender key in Settings before pinging." failure so the caller does not treat a misconfigured app as a successful reference advance.
Nothing in this file constructs a location manager, reads the typed manual label, sleeps, or calls `Date()` other than through `now`.</action>
