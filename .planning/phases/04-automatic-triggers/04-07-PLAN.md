`@MainActor final class LocationDelegateProxy: NSObject, CLLocationManagerDelegate, LocationTriggerSource`:
- `private let manager = CLLocationManager()`, `self.manager.delegate = self` in `init()`. Main-actor isolation both satisfies ARCHITECTURE's rule and puts the manager on the runloop CoreLocation delivers callbacks on (RESEARCH Q5).
- Stored handler closures, installed by `setHandlers(significantChange:visit:)`.
- `startSignificantChange()` / `stopSignificantChange()` → `manager.startMonitoringSignificantLocationChanges()` / `stopMonitoringSignificantLocationChanges()`. `startVisits()` / `stopVisits()` → `startMonitoringVisits()` / `stopMonitoringVisits()`. Nothing else starts or stops.
- `locationManager(_:didUpdateLocations:)` — take `locations.last`, build a `SignificantChangeReport` from its coordinate, `horizontalAccuracy` and `timestamp`, and `Task { await handler(report) }`. Never force-unwrap (ARCHITECTURE Forbidden).
- `locationManager(_:didVisit:)` — build a `VisitReport` from `visit.coordinate`, `visit.horizontalAccuracy`, `visit.arrivalDate`, `visit.departureDate` INSIDE the delegate method, then `Task { await handler(report) }`. Comment names the reason: `CLVisit` is not `Sendable`, so the conversion has to happen here, before anything crosses an isolation boundary.
- `currentAuthorization()` → `manager.authorizationStatus`.
- `requestAlways()` → if the status is `.notDetermined`, call `manager.requestWhenInUseAuthorization()` first (iOS grants Always only as an upgrade from When-In-Use); then `manager.requestAlwaysAuthorization()`; then wait for the status to settle using the SAME bounded poll `CoreLocationFixProvider.currentFix()` already uses (250 ms × 240 = 60 s, then give up and return whatever the status now is). Do not invent an unbounded wait — LEARNINGS and that file both record why the bound exists. Return the final `manager.authorizationStatus`.
- A header comment stating: this is the app's SECOND CLLocationManager (the first, in CoreLocationFixProvider, serves one-shot manual fixes) and why two are correct — different lifetimes, and the manual path must keep working untouched at When-In-Use; and that the continuous-GPS call pattern ARCHITECTURE forbids appears nowhere in this file, which smoke.sh enforces. **Write that sentence WITHOUT naming the three banned identifiers.** 04-01 keeps the ban on those literals unconditional — no file exemption and, deliberately, no comment-strip, because a guard with no exemption is the one shape nothing can escape — so a doc comment spelling them out fails the location guard outright (.planning/LEARNINGS.md: "a comment containing `CLLocationManager` failed the location guard outright") and would also defeat this task's own verify below. Refer to them by description, or by ARCHITECTURE's Forbidden entry, never by literal.</action>
