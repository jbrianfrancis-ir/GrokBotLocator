  <name>Task 1: TriggerLabelProviding and the empty-label default</name>
  <files>src/Triggers/TriggerLabel.swift</files>
  <action>`import Foundation` ONLY. Do not import MapKit. Do not name `CLGeocoder`, `MKReverseGeocodingRequest`, or `MKMapItem` in code — the header comment may name them as prose.

`protocol TriggerLabelProviding: Sendable` — one requirement, `func label(for coordinate: TriggerCoordinate) async -> String`. Non-throwing on purpose: a label is decoration on a ping, and a caller that has to handle a geocoding error is a caller that can fail to send. A conformer that cannot produce a name returns "".

`struct EmptyTriggerLabelProvider: TriggerLabelProviding` — returns "" for every coordinate. This is what the composition root wires (04-13) and what ships.

`func normalisedTriggerLabel(_ raw: String) -> String` (or a `static` on the protocol's extension) — trims whitespace and newlines and returns "" for anything that trims to empty, so a provider returning " " cannot put a blank-looking label on the wire.

File header comment, in prose, stating all of: (a) REQUIREMENTS.md:34 carries an unresolved `[NEEDS CLARIFICATION]` on the geocoder API and nobody has answered it, so the empty label is the shipping behaviour and not a derived one; (b) `CLGeocoder` is soft-deprecated at iOS 26.0 with message "Use MapKit" and its replacement `MKReverseGeocodingRequest` lives in MapKit, which is NOT on ARCHITECTURE's closed `## Frameworks & libraries` list; (c) if a human authorises that addition, the entire change is ONE new file `src/Triggers/MapKitTriggerLabelProvider.swift` conforming to this protocol plus one line at the composition root — no trigger, no coordinator and no test outside this seam moves. Name that file path explicitly so the blast radius is written down.</action>
