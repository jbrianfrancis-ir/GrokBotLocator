  <name>Task 1: TriggerSettings</name>
  <files>src/Settings/TriggerSettings.swift</files>
  <action>`import Foundation` only. `struct TriggerSettings: Sendable, Equatable`:
- `var significantChangeEnabled: Bool`, `var visitsEnabled: Bool`, `var geofenceEnabled: Bool`.
- `private(set) var minimumIntervalSeconds: TimeInterval` — `private(set)` so the only way to change it is the clamping mutator below; a plain `var` is how a 5 gets in.
- `mutating func setMinimumInterval(_ seconds: TimeInterval)` — stores `max(seconds, PingRateLimiter.hardFloor)`; a `.nan` or negative input also lands on the floor (`seconds.isFinite` check first).
- `init(significantChangeEnabled:visitsEnabled:geofenceEnabled:minimumIntervalSeconds:)` running the same clamp.
- `static let initial = TriggerSettings(significantChangeEnabled: false, visitsEnabled: false, geofenceEnabled: false, minimumIntervalSeconds: PingRateLimiter.defaultInterval)` — every trigger off, so a fresh install never prompts for Always (REQ-10).
- `var anyTriggerEnabled: Bool` — true when any of the three is on. This is what 04-12 uses to decide whether to ask for Always at all.
No `UserDefaults`, no `FileManager`, no coordinate, no `Date()` in this file.</action>

  <name>Task 2: TriggerSettingsStoring and its UserDefaults conformer</name>
  <files>src/Settings/TriggerSettingsStore.swift</files>
  <action>`protocol TriggerSettingsStoring: Sendable` — `func load() -> TriggerSettings` and `func save(_ settings: TriggerSettings)`. Non-throwing, matching `PingLabelStore`: a settings write that fails is not something the user can act on, and the in-memory value is still correct for this session.

`struct UserDefaultsTriggerSettingsStore: TriggerSettingsStoring` with `init(defaults: UserDefaults = .standard)`:
- Four namespaced keys, all string constants declared once in this file, e.g. `"triggers.significantChange"`, `"triggers.visits"`, `"triggers.geofence"`, `"triggers.minimumIntervalSeconds"`.
- `load()` — reads the three booleans (absent reads false, which is `TriggerSettings.initial`'s value), reads the interval with `defaults.object(forKey:) as? Double` so an ABSENT key is distinguishable from a stored `0.0`, and falls back to `PingRateLimiter.defaultInterval` when absent. Builds the result through `TriggerSettings.init`, so a hand-edited `5` or a `0` comes back clamped to the floor rather than honoured.
- `save(_:)` — writes all four keys.
File header states why this file is the UserDefaults guard's second exemption: three switches and one number, none of them a credential or a coordinate, and the guard's purpose — keeping the sender key, the webhook URL and coordinates out of UserDefaults — is untouched. Nothing here ever stores a latitude, a longitude or anything from `WebhookCredentials`.</action>

THEN the absence: `grep -nE 'latitude|longitude|senderKey|webhook|Keychain' src/Settings/TriggerSettingsStore.swift` finds nothing (exit 1). Then `SMOKE_DERIVED_DATA=build/dd-04-06 ./scripts/smoke.sh` exits 0 — its UserDefaults guard passes with this file present AND, per 04-01, with `UserDefaultsTriggerSettingsStore` stripped as an allowed token so the type name alone is not a hit.</verify>
  <falsify>Add `defaults.set(41.1171, forKey: "triggers.lastLatitude")` to `save(_:)`: the grep matches `latitude` and exits 0. Revert.</falsify>
  <done>Settings round-trip through UserDefaults with the floor re-applied on read, and nothing else goes in.</done>
