<task type="auto">
  <name>Task 2: FilePingQueueStore</name>
  <files>src/Queue/PingQueueStore.swift</files>
  <action>`actor FilePingQueueStore: PingQueueStoring` — an actor so two drain triggers cannot interleave a read-modify-write.
- `init(directory: URL)` plus `static func applicationSupport() throws -> FilePingQueueStore` resolving `FileManager.default.url(for: .applicationSupportDirectory, in: .userDomainMask, appropriateFor: nil, create: true)`. The injectable directory is what makes every case below testable without touching the app's real queue.
- File name `PingQueue.json`; set-aside name `PingQueue-unreadable.json`.
- `static let capacity = 200`.
- `load()`: no file → `[]`. Decode with `JSONDecoder`; on a decode failure, move the file to the set-aside name (replacing any previous set-aside, never deleting the entries — they were never delivered, so retaining them breaks none of D-12's four conditions) and THEN throw `PingQueueError.unreadable`, so the caller reports an honest failure once and the next call starts clean.
- `write(_ pings:)` (private): `JSONEncoder().encode(pings)` then `data.write(to: url, options: [.atomic, .completeFileProtectionUnlessOpen])`, then set `isExcludedFromBackup = true` through `URLResourceValues` on a `var` copy of the URL. Both, every write — a file recreated by an atomic replace does not inherit the previous file's resource values.
- `append(_ ping:)`: `load()`, throw `.full` if already at `capacity` (an honest refusal the sink turns into a user-visible sentence; NEVER evict the oldest, which would be the silent drop ARCHITECTURE forbids), otherwise append and `write`.
- `replace(with:)`: `write` the given array wholesale — this is how the drain removes a delivered entry.
Document at the top that this file is the ONE sanctioned coordinate store (D-12), quoting the four conditions, and that nothing may copy an entry anywhere else.</action>
  <verify>`SMOKE_DERIVED_DATA=build/dd-03-06 ./scripts/smoke.sh` exits 0, and both tokens appear on real code lines, counted COMMENT-BLIND because this task's own action asks the file header to quote D-12's four conditions, which name the protection option verbatim: `grep -n 'completeFileProtectionUnlessOpen' src/Queue/PingQueueStore.swift | grep -vE '^[0-9]+: *(///|//|\*)' | wc -l` is at least 1, and the same pipeline for `isExcludedFromBackup` is at least 1.</verify>
  <falsify>Change the write options to `[.atomic]` alone: the `completeFileProtectionUnlessOpen` grep reports 0 and the check fails. Revert.</falsify>
  <done>A protected, backup-excluded, capacity-bounded file with no silent eviction and no brick state.</done>
