  <action>Add `enum QueueDrainTask` with two members:
- `static let identifier: String` — the first element of `Bundle.main.object(forInfoDictionaryKey: "BGTaskSchedulerPermittedIdentifiers") as? [String]`, defaulting to `""`. Reading it back from the plist that permits it is what keeps the string in one place and the bundle id out of source (ARCHITECTURE Forbidden).
- `static func request(identifier: String, from now: Date) -> BGAppRefreshTaskRequest?` — returns `nil` when `identifier.isEmpty`, otherwise a `BGAppRefreshTaskRequest(identifier:)` with `earliestBeginDate = now.addingTimeInterval(15 * 60)`. A free function taking its inputs, so the empty case is provable in a test rather than asserted in a comment.

Be honest in the doc comment about what the empty case does and does not cover: `.backgroundTask(.appRefresh:)` is a Scene modifier and `SceneBuilder` offers no conditional form, so scene REGISTRATION is unconditional and an empty identifier would register a useless one. What is guarded is SUBMISSION — `request(identifier:from:)` returns nil, so nothing is ever submitted under a guessed string — and what keeps an empty identifier out of a shipped build is Task 2's guard (c) plus 03-11's built-plist check, which fail the gate before it can ship. Do not claim a runtime branch that is not there.

In `init()`, hoist the transport into a local: `let transport = URLSessionPingTransport(session: WebhookSession.make())`. Then `let queue = try? FilePingQueueStore.applicationSupport()`:
- `queue == nil` → `pending: UnqueuedPingSink()` and no coordinator. The app still sends, and `PingSender`'s existing downgrade reports an honest permanent failure — degrading to phase-02 behaviour, never to a false "Queued".
- otherwise → `pending: DurablePingSink(store: queue, policy: .standard, now: { Date() })`, and after `_pingModel` is assigned build `QueueDrainCoordinator(store: queue, drain: PingQueueDrain(store: queue, credentials: store, transport: transport, policy: .standard, now: { Date() }), model: <the PingModel>, connectivity: NWPathMonitorConnectivity(), now: { Date() })` into a `@State private var coordinator: QueueDrainCoordinator?`.
The SAME `queue` instance reaches both the sink and the drain, and the SAME `transport` reaches both the sender and the drain — one actor over one file, one bounded session.

In `body`: add `@Environment(\.scenePhase) private var scenePhase`; on the `RootView`, `.task { await coordinator?.start() }` and `.onChange(of: scenePhase) { _, phase in if phase == .active { Task { await coordinator?.drainForeground() } } else if phase == .background { scheduleRefresh() } }`; on the `WindowGroup` scene, `.backgroundTask(.appRefresh(QueueDrainTask.identifier)) { await coordinator?.drainBackground() }`.
`private func scheduleRefresh()` — `guard let request = QueueDrainTask.request(identifier: QueueDrainTask.identifier, from: Date()) else { return }`, then `try? BGTaskScheduler.shared.submit(request)`. A scheduling failure is not shown: the file is the durability mechanism and the next foreground drains anyway (ARCHITECTURE — the refresh task is supplementary).
