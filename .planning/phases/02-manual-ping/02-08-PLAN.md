<task type="auto">
  <name>Task 1: PingSender, PingAttempt and the queue seam</name>
  <files>src/Ping/PingSender.swift</files>
  <action>Declare, all `Sendable`:
- `struct PingAttempt: Sendable, Equatable { let fix: LocationFix?; let disposition: PingDisposition; let statusCode: Int?; let responseBody: String? }` — `fix` nil when the attempt never got one; `statusCode`/`responseBody` nil when no HTTP response came back.
- `protocol PendingPingSink: Sendable { func enqueue(_ payload: PingPayload, reason: String) async }` with a doc comment stating plainly that this is phase 03's seam (REQ-05): the durable on-disk queue conforms to it, and until then the outcome the user sees is a recorded failure with a reason, not a silent drop.
- `struct UnqueuedPingSink: PendingPingSink` whose `enqueue` does nothing, with a comment saying so.
- `protocol PingSending: Sendable { func send(label: String) async -> PingAttempt }` and `struct PingSender: PingSending` whose initializer is exactly `init(credentials: CredentialStore, fixes: LocationFixProvider, transport: PingTransport, pending: PendingPingSink)` — those four argument labels, in that order. Plan 02-13 writes that call site verbatim, so the labels are pinned here rather than left to the executor.
`send(label:)` never throws; it returns an attempt:
1. `credentials.load()` — a thrown error or nil gives `.permanentFailure(reason: "Add your webhook URL and sender key in Settings before pinging.")` with `fix`, `statusCode` and `responseBody` all nil, and NO fix and NO POST attempted;
2. `try await fixes.currentFix()` — a `LocationFixError` gives `.permanentFailure(reason: error.reason)`; any other error gives a generic fix-failure sentence. Either way the transport is not called;
3. `transport.send(fix.payload(label: label), using: credentials)`; on a thrown error use `PingClassifier.disposition(forTransportError:)`, on success `PingClassifier.disposition(for: response)` and carry `response.statusCode` and `response.body` into the attempt verbatim;
4. if the disposition is `.retryable`, `await pending.enqueue(payload, reason:)` before returning; if it is `.permanentFailure` or `.sent`, do not call the sink.
Never print, log, or interpolate a credential or a coordinate.</action>
  <verify>`./scripts/smoke.sh` exits 0, and `grep -nE 'print\(|NSLog|os_log|URLSession|FileManager' src/Ping/PingSender.swift` finds nothing (exit 1) — it reaches the network only through the injected protocol.</verify>
  <falsify>Add `private let session = URLSession.shared` to PingSender.swift: the grep matches and exits 0. Revert.</falsify>
  <done>One call, four injected protocols, no network or disk of its own.</done>
