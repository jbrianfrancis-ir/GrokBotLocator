<task type="auto">
  <name>Task 2: request-shape tests through a URLProtocol stub</name>
  <files>tests/PingTransportTests.swift</files>
  <action>`@Suite struct PingTransportTests`. In the same file add `final class StubURLProtocol: URLProtocol` that, via static properties guarded by an `NSLock`, records the request it was handed and replays a caller-set `(statusCode, body)` or a caller-set `Error`. Note `URLProtocol` strips `httpBody` from the request it receives, so capture the body from `request.httpBodyStream` (read it to `Data`) — assert against bytes, not against the `httpBody` property, or the body assertion silently compares nil to nil.
Build the session as `URLSessionConfiguration.ephemeral` with `protocolClasses = [StubURLProtocol.self]`, then `URLSession(configuration:)`. Synthetic credentials only: `https://example.invalid/webhook`, header `X-Test-Key`, key `"not-a-real-key.invalid"`.
Cases: (1) a 200 with body `{"ok":true}` returns `statusCode == 200` and that exact body string; (2) the captured request is POST, its URL is the credential URL, its value for `X-Test-Key` equals the key verbatim (assert it does NOT start with "Bearer "), and its Content-Type is `application/json`. Assert the body two ways: primarily by parsing the captured bytes with `JSONSerialization` and comparing the four fields to the payload's own values — which holds regardless of key order — and then by `#expect(capturedBody == (try payload.encoded()))`. The byte comparison is legitimate ONLY because 02-02 replaced `JSONEncoder`'s dictionary-backed keyed container with a composed string, making `encoded()` byte-stable across calls and processes; before that change this assertion failed most runs. Keep both: the parsed comparison says the right data arrived, the byte comparison says the determinism 02-02 promised still holds; (3) a 204 with empty data returns `body == ""`; (4) a stubbed `URLError(.notConnectedToInternet)` makes `send` throw, and the thrown error is not a `PingTransportError`; (5) only the two headers the transport sets appear among the app-set fields — assert `allHTTPHeaderFields` has no key matching `Authorization` when the credential's header name is `X-Test-Key`.</action>
  <verify>`./scripts/smoke.sh` exits 0 AND its log contains `Suite PingTransportTests passed`.</verify>
  <falsify>In URLSessionPingTransport change the header set to `"Bearer " + credentials.senderKey`: case (2) fails on the header value and the log shows `Suite PingTransportTests failed`. Revert.</falsify>
  <done>Method, URL, headers and body bytes all proven against a stub, with no network call.</done>
