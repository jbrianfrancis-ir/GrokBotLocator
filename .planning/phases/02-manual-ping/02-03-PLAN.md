<objective>
The delivery vocabulary: what a send returned, and whether that means delivered, permanently
rejected, or worth retrying. Pure and testable before any network code exists.
</objective>

<context>
.planning/ARCHITECTURE.md — transport protocol-backed and injected; never log the key, the
URL, or raw coordinates. .planning/DESIGN.md — errors say what happened and what to do next,
never a bare status code. .planning/REQUIREMENTS.md Assumptions: any 2xx accepted; 5xx and
network errors retry with backoff; 401/403 surface immediately and never retry.
From 02-02: src/Core/Ping/PingPayload.swift. Phase 01:
src/Core/Credentials/WebhookCredentials.swift.
Backoff and the durable queue are phase 03 (REQ-05) — classify here, retry there.
`depends_on: [02-02]` is a consumption edge (the protocol's method takes a PingPayload) and
also the phase's build edge: one generated project, one target over all of src/, one
derived-data dir, so concurrent smoke.sh runs would race. The phase is serial for that reason.
Gate: ./scripts/smoke.sh. Swift Testing, never XCTest.
</context>

  <action>Declare, all `Sendable`, in src/Core/Transport/ (new folder):
- `struct PingResponse: Sendable, Equatable { let statusCode: Int; let body: String }` — `body` is the response payload decoded as UTF-8, empty string when there is none.
- `enum PingDisposition: Sendable, Equatable { case sent; case permanentFailure(reason: String); case retryable(reason: String) }`.
- `protocol PingTransport: Sendable { func send(_ payload: PingPayload, using credentials: WebhookCredentials) async throws -> PingResponse }`.
- `enum PingClassifier` with `static func disposition(for response: PingResponse) -> PingDisposition` and `static func disposition(forTransportError error: Error) -> PingDisposition`.
Rules: `200...299` → `.sent`. `401`, `403` → `.permanentFailure("Rejected by the webhook (HTTP \(code)). Check the sender key and header name in Settings.")`. Any other `400...499` → `.permanentFailure("The webhook refused this ping (HTTP \(code)). Check the webhook URL in Settings.")` — this is the branch REQUIREMENTS.md never settled, see backstop_truths. `500...599` → `.retryable("The webhook is unavailable (HTTP \(code)). Try again in a moment.")`. Anything else → `.permanentFailure` naming the code. A thrown error → `.retryable("Could not reach the webhook — check your connection, then tap again.")`, with the error NOT interpolated.
