**Why `encoded()` does not use `JSONEncoder` for the object.** `JSONEncoder` does not serialize
in `CodingKeys` or property-declaration order: its keyed container is dictionary-backed, so key
order is non-deterministic per process under Swift's hash seeding. Measured on the iOS 26
simulator runtime over six consecutive runs of this exact struct, the four keys came out in a
different order nearly every time (`lng,lat,accuracy_m,label`; `label,accuracy_m,lat,lng`;
`lat,accuracy_m,label,lng`; …). `.sortedKeys` is not a fix either — it yields
`accuracy_m,label,lat,lng`. So `encoded()` composes the four fields itself in the order
ARCHITECTURE.md names. That satisfies both the strict reading (the order is a wire requirement)
and the loose one (it is only illustrative), so no human call is needed; the cost is that the
label's escaping must come from Foundation and not from hand-written replacements, which Task 1
pins. Downstream plans depend on this determinism: 02-04 compares captured request bytes to a
second `encoded()` call, which is only legitimate because of it.

New folder: src/Core/Ping/. Gate: ./scripts/smoke.sh. Swift Testing, never XCTest.
`depends_on: [02-01]` is a build edge, not a consumption edge — one XcodeGen-generated project,
one target compiling all of src/, one derived-data dir, so two executors running smoke.sh at
once race on all three. The phase is deliberately serial for that reason.
</context>

<task type="auto">
  <name>Task 1: PingPayload and its deterministic encoder</name>
  <files>src/Core/Ping/PingPayload.swift</files>
  <action>`struct PingPayload: Codable, Sendable, Equatable` with Swift-named stored properties `latitude: Double`, `longitude: Double`, `accuracyMetres: Double`, `label: String`, and a `private enum CodingKeys: String, CodingKey` mapping them to `lat`, `lng`, `accuracy_m`, `label`. `Codable` stays because ARCHITECTURE makes phase 03's offline queue a `Codable` array — but the synthesized encoder is NOT the wire format, and the type comment must say so in one line.

`func encoded() throws -> Data` composes the object itself, in this exact order:
- `enum PingPayloadError: Error { case nonFiniteValue }` in the same file; throw it unless all three of `latitude`, `longitude` and `accuracyMetres` are `.isFinite` — `"\(Double.infinity)"` is `inf`, which is not a JSON number, and a fail-closed refusal beats emitting a body the routine cannot parse;
- render each number with string interpolation of the `Double` (`"\(latitude)"`). Swift's description is the shortest round-trippable decimal form, so 40.77465 stays `40.77465` and an integral value renders `17.0`, which is a valid JSON number;
- escape the label with Foundation, never by hand: `let quoted = try JSONEncoder().encode([label])` gives bytes like `["a\"b"]` — an ARRAY, whose order is defined, so none of the keyed-container non-determinism applies — and `String(decoding: quoted.dropFirst().dropLast(), as: UTF8.self)` is the label as a complete JSON string literal, quotes and escapes included. Do not write `replacingOccurrences` for quotes, backslashes, newlines or control characters;
- assemble `{"lat":\(lat),"lng":\(lng),"accuracy_m":\(acc),"label":\(quotedLabel)}` and return its UTF-8 `Data`.

`label` is always present, empty string included — never an optional, never omitted. Never print, log, or hold a credential.</action>

  <falsify>Add `.sortedKeys` to the label escaper's `JSONEncoder().outputFormatting`: the grep matches and exits 0. Revert.</falsify>
  <done>One type, one deterministic encoder, four keys in ARCHITECTURE's order, Foundation doing the escaping.</done>

  <action>`@Suite struct PingPayloadTests` over synthetic values only. From `PingPayload(latitude: 40.77465, longitude: 17.23107, accuracyMetres: 12.5, label: "Gallipoli")`:
- `@Test func encodesExactlyTheFourKeysWithTheRightTypes()` — parse `encoded()` with `JSONSerialization.jsonObject` into `[String: Any]`, assert `Set(dict.keys) == ["lat","lng","accuracy_m","label"]`, assert `dict["lat"] is NSNumber` (same for lng and accuracy_m) and `dict["label"] is String`, then assert the values are 40.77465 / 17.23107 / 12.5 / "Gallipoli". Asserting the type is the point: a Double accidentally written through `String(…)` would still round-trip as the right text;
- `@Test func keysAppearInTheOrderArchitectureNames()` — on the UTF-8 string of `encoded()`, take `range(of:)` for `"lat"`, `"lng"`, `"accuracy_m"`, `"label"` and assert the four lower bounds are strictly increasing;
- `@Test func encodingIsByteStableAcrossCalls()` — encode the same value 50 times and assert every result equals the first. This is the determinism 02-04 relies on, and 50 iterations is enough that a dictionary-ordered encoder would fail it essentially always;
- `@Test func anEmptyLabelStillEmitsTheKey()` — `label: ""` yields a `label` key (assert via `dict.keys.contains`, not a nil check on the value) whose value is `""`;
- `@Test func foundationEscapesAnAwkwardLabel()` — `"Santa Maria di \"Leuca\"\nPuglia — café"` encodes to valid JSON and re-parsing gives back the identical String. Also assert the raw bytes contain `\\"` and `\\n` escape sequences rather than a literal quote or newline inside the string, which is what proves the escaping happened at all;
- `@Test func refusesNonFiniteValues()` — over `Double.infinity`, `-.infinity` and `Double.nan` in each of the three numeric positions, `encoded()` throws, and the thrown error is `PingPayloadError.nonFiniteValue`.</action>
