<task type="auto">
  <name>Task 1: CoreLocationFixProvider</name>
  <files>src/Core/Location/CoreLocationFixProvider.swift</files>
  <action>`@MainActor final class CoreLocationFixProvider: LocationFixProvider`, holding one `private let manager = CLLocationManager()`. Main-actor isolation is the "one actor-isolated coordinator" ARCHITECTURE asks for, and it keeps CLLocationManager on the thread CoreLocation expects; views still reach it only through the protocol.
`authorizationNotice()` returns `LocationAuthorizationNotice.notice(for: manager.authorizationStatus)`.
`currentFix()`:
1. If `manager.authorizationStatus == .notDetermined`, call `manager.requestWhenInUseAuthorization()` — this, and only this, is the point-of-use request — then wait for the status to change by polling `manager.authorizationStatus` every 250 ms with `try await Task.sleep(for: .milliseconds(250))`, for AT MOST 60 s (240 polls), then throw `LocationFixError.notAuthorized`. The bound is not optional: the window is generous because a human is reading a system prompt, but a user who backgrounds the app at that prompt leaves the status `.notDetermined` indefinitely, and an unbounded wait would hold 02-09's `isInFlight` true for the life of the process — a spinning button with no sentence, which DESIGN.md forbids.
2. Map the resolved status: `.denied` → throw `LocationFixError.notAuthorized`, `.restricted` → `.deniedGlobally`, anything not authorized → `.notAuthorized`.
3. Race two children in a `withThrowingTaskGroup`: one iterating `CLLocationUpdate.liveUpdates(.default)`, one sleeping 8 s then throwing `LocationFixError.timedOut`. In the stream, skip updates while `update.authorizationRequestInProgress` is true; throw `.deniedGlobally` on `update.authorizationDeniedGlobally`, `.notAuthorized` on `update.authorizationDenied`, `.unavailable` on `update.locationUnavailable`; on the first non-nil `update.location`, return `try LocationFix.validated(latitude: location.coordinate.latitude, longitude: location.coordinate.longitude, horizontalAccuracy: location.horizontalAccuracy, timestamp: location.timestamp)` — 02-05 owns the negative-accuracy refusal and its tests, so do NOT re-implement that check here and do NOT call `LocationFix`'s memberwise init. Cancel the group on the first result either way — never leave the stream running.
Never call `requestAlwaysAuthorization`, `startUpdatingLocation`, or set `allowsBackgroundLocationUpdates`. Never force-unwrap a `CLLocation`. Never print, log, or interpolate a coordinate.</action>
  <verify>`./scripts/smoke.sh` exits 0; `grep -nE 'requestAlwaysAuthorization|startUpdatingLocation|allowsBackgroundLocationUpdates|location!|print\(' src/Core/Location/CoreLocationFixProvider.swift` finds nothing (exit 1); and `grep -c 'LocationFix.validated' src/Core/Location/CoreLocationFixProvider.swift` prints 1 while `grep -c 'LocationFix(' src/Core/Location/CoreLocationFixProvider.swift` prints 0 — the guarded factory is the only constructor this file uses.</verify>
  <falsify>Add `manager.requestAlwaysAuthorization()` beside the When-In-Use call: the grep matches and exits 0. Revert.</falsify>
  <done>One fix, requested at the point of use, with no continuous updates and no Always.</done>
