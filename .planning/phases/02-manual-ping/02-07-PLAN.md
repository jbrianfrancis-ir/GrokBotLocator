<objective>
Two small stores the ping flow needs: the label that survives between pings (REQ-03) and the
history log the screen lists (REQ-04). Both pure and injectable, so the model above them is
testable with no UserDefaults and no disk.
</objective>

<context>
.planning/ARCHITECTURE.md — credentials live only in the Keychain, never in UserDefaults.
A ping label is user-typed text, not a credential and not a coordinate, so UserDefaults is the
right home for it; nothing in this plan may put a URL, a key, or a coordinate there.
.planning/REQUIREMENTS.md REQ-03, REQ-04. Phase 01: `PingOutcome` (sent / queued / failed) in
src/Core/DesignSystem/PingOutcomeRow.swift.
The on-disk durable queue is phase 03 (REQ-05): this phase's history is in memory for the
session only, which is why REQ-04's acceptance asks for two rows in one run and nothing more.
New folder: src/Ping/. Gate: ./scripts/smoke.sh. Swift Testing, never XCTest.
`depends_on: [02-06]` is the phase's build edge (one generated project, one target over all of
src/, one derived-data dir, so concurrent smoke.sh runs would race), not a consumption edge.
</context>
