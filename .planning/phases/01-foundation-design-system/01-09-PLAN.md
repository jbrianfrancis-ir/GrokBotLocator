<objective>
The entitlement wiring the Keychain needs. Without it every SecItem call in 01-10 fails,
so this must land before any test touches the Keychain.
</objective>

<context>
Causation, isolated by experiment — do not confuse these:
- On SIMULATOR, **hosting is what fixes -34018**. A hosted test bundle with NO entitlement
  passes the SecItem round trip. The original failure came from the bundle being unhosted.
- The `keychain-access-groups` entitlement matters on DEVICE, where a real keychain access
  group is required. It is not optional; it is simply not what the simulator exercises.

Consequence for verification: `./scripts/smoke.sh` CANNOT detect a gutted or missing
entitlements file — it will stay green. Only 01-10's on-device human check can. Do not
treat a green smoke run as proof the entitlement is correct.

ARCHITECTURE.md forbids a literal bundle id or team id in any tracked file, so the
entitlement must use build-setting substitution.
</context>

<tasks>
<task type="auto">
  <name>Task 1: The entitlements file</name>
  <files>GrokBotLocator.entitlements</files>
  <action>A plist whose `keychain-access-groups` array holds exactly `$(AppIdentifierPrefix)$(PRODUCT_BUNDLE_IDENTIFIER)`. Use the substitution, never a literal — both values resolve from the gitignored Signing.xcconfig at build time, and ARCHITECTURE.md forbids either literal in a tracked file.</action>
  <verify>`grep -q 'keychain-access-groups' GrokBotLocator.entitlements`; then `sed 's/$([^)]*)//g' GrokBotLocator.entitlements | grep -nE '[A-Z0-9]{10}|com\.[a-z0-9]+\.[a-z0-9]+'; test $? -eq 1` — strip the substitutions BEFORE scanning, or the check can never pass: IDENTIFIER is itself ten uppercase characters.</verify>
  <done>The entitlement exists and carries no identifier literal.</done>
</task>

<task type="auto">
  <name>Task 2: Wire it into the app target</name>
  <files>project.yml</files>
  <action>Add `CODE_SIGN_ENTITLEMENTS: GrokBotLocator.entitlements` to the app target's settings. The app target already sets CODE_SIGN_IDENTITY "-" from 01-01; do not add DEVELOPMENT_TEAM.
Do NOT add TEST_HOST or BUNDLE_LOADER by hand: XcodeGen emits both from the test target's `dependencies: [target: GrokBotLocator]`, present since 01-01.
Never pass CODE_SIGNING_ALLOWED=NO anywhere — it strips entitlements, which matters on device.</action>
  <verify>`grep -q CODE_SIGN_ENTITLEMENTS project.yml`; `xcodegen generate` exits 0; `grep -c 'TEST_HOST' GrokBotLocator.xcodeproj/project.pbxproj` >= 1, proving hosted tests; `./scripts/smoke.sh` exits 0.
Note: smoke passing does NOT prove the entitlement is right — on simulator, hosting alone makes SecItem work. Only 01-10's device check covers it.</verify>
  <done>The app target references the entitlement and tests run hosted.</done>
</task>
