<task type="auto">
  <name>Task 2: Keychain implementation</name>
  <files>src/Core/Credentials/KeychainCredentialStore.swift</files>
  <action>A struct conforming to CredentialStore — the only type in the app calling SecItem APIs. `kSecClassGenericPassword`; `kSecAttrService` from an injectable service string defaulting to the bundle identifier (so tests can pass a throwaway one); one item per field with `kSecAttrAccount` of "webhook.url", "webhook.senderKey", "webhook.headerName"; `kSecAttrAccessible` = `kSecAttrAccessibleAfterFirstUnlock`, so later phases can send from the background.
save: SecItemUpdate, falling back to SecItemAdd on errSecItemNotFound, so re-saving overwrites instead of duplicating.
load: SecItemCopyMatching per account; return nil if url or senderKey is missing. A missing headerName falls back to defaultHeaderName; url and senderKey never get a stand-in.
clear: SecItemDelete per account, with errSecItemNotFound treated as success.
Any other status throws CredentialStoreError. No print, NSLog, or os_log in the file, and no value ever placed in UserDefaults.</action>
  <verify>`./scripts/smoke.sh` exits 0; `grep -rniE 'print\(|NSLog|os_log|UserDefaults' src/Core/Credentials/` is empty; `grep -rl SecItem src/` lists only this file.</verify>
  <done>Round-trip storage implemented, re-save overwrites, and no fallback exists for url or key.</done>
</task>
